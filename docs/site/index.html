SQLodin is a distributed SQL database. Send a write to any voter. Paxos gives the cluster one ordered history, stored on disk.

01 / Write anywhere

Every voter can propose.

Rotating slot ownership lets voters admit writes without forwarding each request to a standing leader. The cluster still agrees on one order.

02 / Use familiar tools

SQL, from a terminal or Python.

An interactive CLI, parameter binding, transactions and SQLAlchemy. FTS5 and exact vector search work alongside structured records.

03 / Keep the evidence

Durability you can examine.

A durable Paxos journal, replayable application state, authenticated peers and explicit retry identities. Read the models, tests and design decisions.

Start with a local file

A query before
a cluster.

The executable includes a local SQLite shell. Try it first, then follow the service guide to configure certificates and replicated voters.

Set up a cluster ↗
TERMINAL · LINUX x86-64
curl -fLO https://github.com/insanai/sqlodin/releases/latest/download/sqlodin-linux-amd64.tar.gz
tar -xzf sqlodin-linux-amd64.tar.gz
./sqlodin local notes.db

CREATE TABLE note (id INTEGER PRIMARY KEY, body TEXT);
INSERT INTO note VALUES (1, 'Hello, SQLodin');
SELECT * FROM note;

-- A local file is not yet a replicated database.

Read the measured workloads ↗

The 0.6.0 server accepts one to five fixed voters. Release qualification used three voters; targeted tests and models also cover five. Replication does not shard the database or remove SQLite's single-writer constraint. Supported SQL and transaction sizes have explicit bounds.
